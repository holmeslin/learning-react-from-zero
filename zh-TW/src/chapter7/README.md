# 管理複雜 state

專案小的時候，把 state 放在需要它的元件裡，再用 props 往下傳，就已經很夠用了。但隨著功能越來越多，你會遇到兩種痛：

- **更新 state 的邏輯散落各處**：新增、勾選、刪除、排序……每個事件處理函式都各自改一點 state，要找出「這份資料到底有哪些改法」得翻遍整個元件。
- **props 要穿過一層又一層**：最上層的元件持有資料，最下層的元件才用得到，中間每一層都得幫忙轉傳。

這一章用三個工具解決這兩種痛：

- `useReducer`：把更新 state 的邏輯集中到一個地方。
- `useContext`：讓深處的元件直接拿到資料，不必一層一層傳 props。
- 兩者合用：資料與更新方法都放進 Context，整個應用程式都能取用。

最後一集會聊聊效能最佳化：`memo`、`useMemo`、`useCallback`，以及 React Compiler 怎麼改變了這件事。

這一章的範例同樣放在 `hello-react` 專案的 `src/App.jsx` 裡執行。
