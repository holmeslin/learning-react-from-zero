# 測試

你寫完一個功能，怎麼知道它是對的？最直接的做法是打開網頁，自己點一點、輸入一些東西，看結果對不對。小專案這樣就夠了。

但專案會長大。三個月後你改了一個元件，要怎麼確定沒有弄壞其他地方？難道每次都把網站從頭到尾手動點一遍嗎？這時候就需要**自動化測試**：把「點這裡、輸入那個、結果應該是這樣」寫成程式，需要的時候一個指令就全部跑完，幾秒鐘內告訴你哪裡壞了。

這一章用的工具組合是目前 React 專案的主流：

- **Vitest**：執行測試的工具。它和 Vite 共用設定，速度很快。
- **React Testing Library**：在測試裡渲染元件、找畫面上的東西的函式庫。
- **user-event**：在測試裡模擬使用者的點選與打字。

這一章的重點不是記住一堆 API，而是學會一種想法：**測試要站在使用者的角度**。使用者看到的是畫面上的文字、按鈕、輸入框，不是元件內部的 state 叫什麼名字。好的測試像一個很有耐心的使用者，照著說明書一步一步操作，然後檢查看到的畫面對不對。這樣的測試，即使你把元件內部整個改寫，只要畫面行為沒變，測試就不用跟著改。

這一章在第 10 章改成 TypeScript 的 `hello-react` 裡進行，測試也用 TypeScript 寫，所以需要先讀完第 9、10 章。測試的對象盡量用前面寫過的東西，例如第 9 章的商品網站。這一章不會用到第二部的 Next.js，Next.js 專案的測試設定比較複雜，不在這本書的範圍內。
