# 為什麼普通變數不行

## 本集目標

親眼看到普通變數無法讓畫面更新，理解為什麼需要 state。

## 正文

### 一個直覺的做法

我們想做一個計數器：按一下按鈕，數字加一。以你目前學到的東西，最自然的寫法是用一個變數。把 `src/App.jsx` 換成：

```jsx
function App() {
  let count = 0;

  function handleClick() {
    count = count + 1;
    console.log("count 現在是", count);
  }

  return (
    <div>
      <p>已點 {count} 次</p>
      <button onClick={handleClick}>加一</button>
    </div>
  );
}

export default App;
```

存檔後，打開 Console，然後連續點按鈕三次。

你會看到 Console 印出：

```text
count 現在是 1
count 現在是 2
count 現在是 3
```

變數的確一直在增加。但是看看網頁：`已點 0 次`，**畫面完全沒有變**。

### 為什麼不行

有兩個原因，兩個都是致命的。

**原因一：改變一個變數，React 不知道。**

React 不會一直盯著你的變數看。它只有在被通知的時候，才會重新執行你的元件函式、更新畫面。你改了 `count`，但沒有任何人通知 React，所以畫面沒有重新繪製。

這裡有一個重要的詞：**渲染**（render）。它的意思是「React 呼叫你的元件函式，根據回傳的 JSX 算出畫面」。畫面要更新，就必須再渲染一次。

**原因二：就算重新渲染，變數也會被重設。**

假設 React 真的重新渲染了，它會再執行一次 `App` 這個函式，也就是從頭再跑一遍：

```jsx,ignore
let count = 0;
```

`count` 又被設成 0。因為每次渲染都是重新呼叫函式，函式裡的普通變數在每次呼叫時都是全新的，上一次累積的結果完全不會留下來。

### 我們需要什麼

所以，要做出會變動的畫面，需要一個東西同時做到兩件事：

1. **在重新渲染之間，記得住資料。**
2. **資料改變的時候，通知 React 重新渲染。**

React 提供的這個東西，就叫 **state**（狀態）。你可以把它想成「元件自己的記憶」。下一集就來用它。

## 重點整理

- 改變普通變數，不會讓畫面更新，因為 React 不知道你改了。
- 每次渲染都會重新執行元件函式，普通變數會被重設。
- 會隨著操作而改變、而且要顯示在畫面上的資料，需要用 state 來保存。
- 渲染就是 React 呼叫元件函式、算出畫面的過程。
