# 為什麼需要框架

## 本集目標

看懂 Vite 專案和 Next.js 專案在「瀏覽器收到什麼」上的差別，並且知道框架幫你做了哪些事。

## 正文

### 瀏覽器收到的是什麼

打開你第一部做的任何一個 Vite 專案，看一下專案根目錄的 `index.html`。去掉設定之後，重點只有這幾行：

```html
<body>
  <div id="root"></div>
  <script type="module" src="/src/main.jsx"></script>
</body>
```

`<div id="root"></div>` 是空的。使用者打開網站時，瀏覽器先拿到這個空殼，再去下載 JavaScript，等 React 執行完，才把畫面一塊一塊畫進 `#root` 裡。

你可以自己驗證：在瀏覽器網址列的最前面加上 `view-source:`，例如 `view-source:http://localhost:5173/`，就能看到伺服器真正送來的 HTML。你會發現畫面上的文字一個字都沒有。

### 空殼會帶來什麼問題

- **使用者會先看到空白**。JavaScript 下載、執行完之前，畫面上什麼都沒有。網路慢或手機比較舊的時候特別明顯。
- **有些工具讀不到內容**。不執行 JavaScript 的工具，例如部分搜尋引擎爬蟲，或是你把網址貼到聊天軟體時產生預覽的程式，看到的就是那個空殼。
- **資料要等很久**。第 6 章你用 `useEffect` 抓資料：先下載 JavaScript、渲染出元件、`useEffect` 才開始發出請求、資料回來之後才能畫出內容。每一步都排在前一步後面。
- **功能要自己拼起來**。路由要裝 React Router、圖片要自己最佳化、字型要自己處理，每個選擇都是你的功課。

### 框架做了什麼

**框架**（framework）是一套「已經把常見決定都做好」的工具。Next.js 在 React 之上多做了這幾件事：

- **在伺服器上先渲染**。伺服器先把 React 元件算成 HTML 再送出去，瀏覽器一收到就有內容可以看。
- **用資料夾決定網址**。不用另外裝路由函式庫，資料夾怎麼放，網址就怎麼長。
- **在伺服器上讀資料**。元件可以直接在伺服器上讀資料，不用等瀏覽器載入完再發請求。
- **內建圖片和字型最佳化**，也包含建置和部署的流程。

同一個「關於我們」頁面，用 Next.js 做出來之後，`view-source:` 看到的 HTML 會是這樣：

```html
<main><h1>關於我們</h1><p>我們是一間很小的書店。</p></main>
```

文字已經在 HTML 裡了。第 5 集你會親手做出這個頁面，到時候再自己看一次。

### 要付出的代價

天下沒有白吃的午餐，用框架也有代價：

- 要用到第二部教的大部分功能，你的網站需要一個會執行 JavaScript 的伺服器（Node.js），不能只丟一堆靜態檔案就好。
- 多了一組新規則要學：哪些程式碼跑在伺服器上、哪些跑在瀏覽器上、兩邊怎麼合作。這就是第 13 章和第 14 章的內容。

這些代價換來的好處，在做內容比較多、需要被搜尋到、或是資料要從伺服器讀的網站時特別值得。如果你只是做一個純粹在瀏覽器裡玩的小工具，Vite 加 React 依然是很好的選擇。

## 重點整理

- Vite 專案送給瀏覽器的是空的 `<div id="root"></div>`，畫面要等 JavaScript 執行完才出現。
- Next.js 會先在伺服器上把畫面算成 HTML，瀏覽器一收到就有內容。
- 框架幫你決定了路由、資料讀取、圖片字型最佳化等常見問題。
- 代價是需要伺服器，而且要學「哪段程式跑在哪裡」的新規則。
- 在網址前面加 `view-source:` 可以看到伺服器真正送出的 HTML。
